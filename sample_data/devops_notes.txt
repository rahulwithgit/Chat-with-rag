DevOps Fundamentals

DevOps is a set of practices that combines software development (Dev) and IT
operations (Ops). The goal is to shorten the development lifecycle and deliver
high-quality software continuously. Key principles include automation,
continuous integration, continuous delivery, infrastructure as code, monitoring,
and collaboration between teams.

Continuous Integration (CI)

CI is the practice of merging all developer working copies to a shared mainline
several times a day. Every merge triggers an automated build and test pipeline.
Popular CI tools include Jenkins, GitHub Actions, GitLab CI/CD, CircleCI, and
Travis CI. A good CI pipeline runs unit tests, linting, static analysis, and
security scans on every push. Fast feedback loops help catch bugs early before
they reach production.

Continuous Delivery and Continuous Deployment (CD)

Continuous Delivery ensures that code changes are automatically built, tested,
and prepared for release to production. Continuous Deployment goes one step
further by automatically deploying every change that passes all pipeline stages
to production without manual intervention. Blue-green deployments, canary
releases, and rolling updates are common deployment strategies used to reduce
risk during releases.

Version Control with Git

Git is the most widely used distributed version control system. Branching
strategies like Git Flow, GitHub Flow, and trunk-based development help teams
collaborate efficiently. Key commands include git clone, git branch, git merge,
git rebase, git stash, and git cherry-pick. Pull requests (or merge requests)
enable code review before changes are merged into the main branch.

Containerization with Docker

Docker packages applications and their dependencies into lightweight containers
that run consistently across environments. A Dockerfile defines the image build
steps. Key concepts include images, containers, volumes, networks, and
registries. Docker Compose allows defining multi-container applications using a
YAML file. Best practices include using small base images like Alpine, running
as a non-root user, leveraging multi-stage builds, and keeping layers minimal.

Container Orchestration with Kubernetes

Kubernetes (K8s) automates deployment, scaling, and management of containerized
applications. Core objects include Pods (smallest deployable unit), Deployments
(manage replica sets), Services (expose pods to network traffic), ConfigMaps,
Secrets, and Ingress controllers. Helm is a package manager for Kubernetes that
uses charts to define, install, and upgrade applications. kubectl is the CLI
tool used to interact with Kubernetes clusters. Common commands include kubectl
get pods, kubectl describe deployment, kubectl apply -f, and kubectl logs.

Infrastructure as Code (IaC)

IaC manages and provisions infrastructure through machine-readable definition
files rather than manual processes. Terraform by HashiCorp is the most popular
multi-cloud IaC tool. It uses HCL (HashiCorp Configuration Language) and
follows a plan-apply workflow. Ansible is an agentless configuration management
tool that uses YAML playbooks to automate server setup and application
deployment. Pulumi allows writing IaC in general-purpose programming languages
like Python, TypeScript, and Go. CloudFormation is the AWS-native IaC service.

Linux Essentials for DevOps

Most servers run Linux. Essential skills include file system navigation (ls, cd,
find, grep), process management (ps, top, htop, kill, systemctl), networking
(curl, wget, netstat, ss, ip, nslookup, dig), file permissions (chmod, chown),
package management (apt, yum, dnf), disk usage (df, du), and log inspection
(journalctl, tail -f /var/log/syslog). Shell scripting with Bash automates
repetitive tasks and is a core DevOps skill.

Networking Basics

Understanding networking is critical for DevOps. Key concepts include the
OSI model (7 layers), TCP/IP, DNS resolution, HTTP/HTTPS, load balancing,
reverse proxies, firewalls, and VPNs. CIDR notation is used for IP addressing.
Common ports include 22 (SSH), 80 (HTTP), 443 (HTTPS), 3306 (MySQL), 5432
(PostgreSQL), 6379 (Redis), and 27017 (MongoDB). Tools like nginx and HAProxy
are used for load balancing and reverse proxying.

Monitoring and Observability

Monitoring tracks system health using metrics, logs, and traces. Prometheus
collects time-series metrics and pairs with Grafana for visualization and
dashboards. The ELK stack (Elasticsearch, Logstash, Kibana) or its lighter
alternative EFK (Elasticsearch, Fluentd, Kibana) handles centralized logging.
Jaeger and Zipkin provide distributed tracing. Alerting tools like PagerDuty
and Opsgenie notify on-call engineers when thresholds are breached. The four
golden signals of monitoring are latency, traffic, errors, and saturation.

Cloud Providers

The three major cloud providers are AWS (Amazon Web Services), Azure (Microsoft),
and GCP (Google Cloud Platform). Core services to know include compute (EC2,
Azure VMs, GCE), storage (S3, Azure Blob, GCS), databases (RDS, Cloud SQL),
networking (VPC, subnets, security groups), and identity management (IAM).
Serverless options like AWS Lambda, Azure Functions, and Google Cloud Functions
allow running code without managing servers. Understanding pricing models,
regions, and availability zones is important for cost optimization.

CI/CD Pipeline Example

A typical pipeline has these stages: (1) Source — code is pushed to a Git
repository. (2) Build — the application is compiled or a Docker image is built.
(3) Test — unit tests, integration tests, and end-to-end tests run. (4) Security
scan — tools like Trivy, Snyk, or SonarQube check for vulnerabilities.
(5) Artifact storage — built artifacts are pushed to a registry like Docker Hub,
ECR, or Nexus. (6) Deploy to staging — the artifact is deployed to a staging
environment for QA. (7) Deploy to production — after approval or automated
checks, the artifact goes live.

Security in DevOps (DevSecOps)

DevSecOps integrates security into every stage of the DevOps pipeline. Practices
include secret management (HashiCorp Vault, AWS Secrets Manager), image scanning,
dependency vulnerability scanning (Dependabot, Snyk), network policies in
Kubernetes, RBAC (Role-Based Access Control), TLS/SSL everywhere, and regular
penetration testing. Shift-left security means catching vulnerabilities as early
as possible in the development cycle.

GitOps

GitOps uses Git as the single source of truth for declarative infrastructure and
applications. Tools like ArgoCD and Flux watch a Git repository and
automatically reconcile the desired state defined in YAML manifests with the
actual cluster state. Any change to infrastructure or application configuration
is made via a pull request, providing an audit trail and enabling rollback by
reverting a commit.

Service Mesh

A service mesh manages communication between microservices. Istio and Linkerd
are popular choices. They provide traffic management, mutual TLS for encryption,
observability (metrics, logs, traces between services), and fault injection for
chaos testing. A sidecar proxy (like Envoy) runs alongside each service to
intercept all network traffic transparently.

Site Reliability Engineering (SRE)

SRE applies software engineering principles to operations. Key concepts include
SLIs (Service Level Indicators), SLOs (Service Level Objectives), SLAs (Service
Level Agreements), error budgets, toil reduction, blameless postmortems, and
incident management. The goal is to balance reliability with feature velocity.
Google popularized SRE and published the SRE book as a free resource.

Software Development Life Cycle (SDLC)

SDLC is the process used to design, develop, and test software. Common models
include Waterfall (sequential phases), Agile (iterative sprints), Scrum (a
framework within Agile using sprints, standups, and retrospectives), and Kanban
(visual workflow boards). Agile is the most widely adopted methodology in modern
software teams. Key ceremonies in Scrum include sprint planning, daily standup,
sprint review, and sprint retrospective.

APIs and Web Services

An API (Application Programming Interface) allows different software systems to
communicate. REST (Representational State Transfer) is the most common API style,
using HTTP methods like GET, POST, PUT, PATCH, and DELETE. GraphQL is an
alternative that lets clients request exactly the data they need. gRPC uses
Protocol Buffers for fast binary communication between microservices. API
gateways like Kong and AWS API Gateway handle authentication, rate limiting,
and routing.

Databases and Data Management

Relational databases (PostgreSQL, MySQL, MariaDB) use SQL and are great for
structured data with relationships. NoSQL databases include document stores
(MongoDB, CouchDB), key-value stores (Redis, DynamoDB), column-family stores
(Cassandra, HBase), and graph databases (Neo4j). Choosing between SQL and NoSQL
depends on data structure, scale, consistency needs, and query patterns. Database
migrations should be versioned and automated using tools like Flyway, Liquibase,
or Alembic.

Microservices Architecture

Microservices break an application into small, independent services that
communicate over APIs. Each service owns its data and can be deployed
independently. Benefits include scalability, technology diversity, and fault
isolation. Challenges include distributed tracing, data consistency, network
latency, and operational complexity. The alternative is a monolithic architecture
where the entire application runs as a single unit. Many teams start monolithic
and migrate to microservices as they scale.

Testing and Quality Assurance

Testing ensures software works as expected. Unit tests verify individual
functions or methods. Integration tests check how components work together.
End-to-end (E2E) tests simulate real user flows. Popular testing frameworks
include pytest (Python), JUnit (Java), Jest (JavaScript), and Go's built-in
testing package. Test-Driven Development (TDD) writes tests before code.
Code coverage tools measure how much code is exercised by tests, but high
coverage alone does not guarantee quality.

Logging Best Practices

Effective logging helps debug issues faster. Use structured logging (JSON format)
for machine-parseable logs. Include context like request IDs, user IDs, and
timestamps. Use log levels appropriately: DEBUG for development details, INFO for
normal operations, WARN for recoverable issues, ERROR for failures that need
attention, and FATAL for crashes. Avoid logging sensitive data like passwords,
tokens, or personal information. Centralize logs using tools like the ELK stack,
Fluentd, Datadog, or Splunk.

Configuration Management

Configuration management ensures servers and environments are set up consistently.
Tools include Ansible (agentless, YAML playbooks), Chef (Ruby-based, uses
cookbooks), Puppet (declarative, uses manifests), and SaltStack. The principle
of idempotency means running a configuration script multiple times produces the
same result. Configuration drift happens when servers diverge from their defined
state, which these tools help prevent.

Caching Strategies

Caching stores frequently accessed data closer to the consumer to reduce latency
and load. Common layers include browser cache, CDN cache (CloudFront, Cloudflare),
application cache (Redis, Memcached), and database query cache. Cache
invalidation strategies include TTL (Time To Live), write-through, write-behind,
and cache-aside patterns. The hardest problem in caching is knowing when to
invalidate stale data.

Message Queues and Event-Driven Architecture

Message queues decouple producers from consumers. Popular tools include RabbitMQ,
Apache Kafka, AWS SQS, and NATS. Kafka is widely used for event streaming and
log aggregation. Event-driven architecture allows services to react to events
asynchronously, improving scalability and resilience. Common patterns include
publish-subscribe, event sourcing, and CQRS (Command Query Responsibility
Segregation).

General Knowledge and Soft Skills for DevOps

DevOps is not just about tools; it is a culture of collaboration between
development and operations teams. Communication, empathy, and shared
responsibility are essential. Blameless postmortems after incidents focus on
learning rather than finger-pointing. Documentation should be kept up to date
and accessible. Automation should be applied wherever manual, repetitive tasks
(called toil) exist. Continuous learning is important because the DevOps
ecosystem evolves rapidly with new tools, practices, and cloud services.

Common Interview Topics in DevOps

Frequently asked DevOps interview topics include explaining the difference
between CI and CD, describing how Docker differs from virtual machines,
explaining Kubernetes pods and services, writing a basic Dockerfile or
docker-compose file, describing a CI/CD pipeline you have built, explaining
blue-green vs canary deployments, describing how you handle secrets in
production, explaining the CAP theorem (Consistency, Availability, Partition
tolerance), and discussing how to monitor and alert on system health. Being able
to explain trade-offs and real-world experience matters more than memorizing
definitions.

Troubleshooting and Debugging

When something breaks in production, a structured approach helps. Start by
checking monitoring dashboards and recent deployments. Look at logs for errors
or unusual patterns. Reproduce the issue in a staging environment if possible.
Use tools like strace, tcpdump, netstat, and kubectl logs for deeper
investigation. Common root causes include configuration errors, resource
exhaustion (CPU, memory, disk), network issues, dependency failures, and
race conditions. Always document the incident and resolution in a postmortem.
